Magic Estimation: ein langes Backlog in Minuten schätzen

Planning Poker braucht ein paar Minuten pro Ticket. Bei fünfzig Tickets ist das ein Nachmittag. Magic Estimation sortiert sie zuerst still und spart das Gespräch für die, bei denen das Team uneinig ist.

So funktioniert es

  1. Der Host öffnet das Sortier-Board: eine Spalte pro Karte des Decks.
  2. Die Spieler ziehen Tickets auf die Spalte, die sie für passend halten, ohne zu reden. Jeder darf jedes Ticket bewegen.
  3. Ein Ticket, das dreimal bewegt oder von jemand anderem auf eine andere Karte gezogen wurde, wird für ein Gespräch markiert.
  4. Der Host schickt die markierten Tickets in eine normale Abstimmung und macht den Rest in einem Schritt zu endgültigen Schätzungen.

Wann es passt

Nutze es fürs Refinement eines großen Backlogs, für ein neues Projekt oder vor der Release-Planung. Für die paar Tickets des nächsten Sprints, bei denen Details zählen, nimm normales Planning Poker.

Die Schätzungen zählen in Velocity, Berichten und Referenz-Historie wie abgestimmte und lassen sich zusammen in Jira, GitHub, Linear oder Azure DevOps speichern.
