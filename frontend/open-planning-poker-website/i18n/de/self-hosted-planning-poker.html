Planning Poker selbst hosten

Open Planning Poker ist Open Source (GPL-3.0). Du kannst es kostenlos auf openplanningpoker.com nutzen oder auf deinen eigenen Servern betreiben, wenn Schätzungen, Ticketnamen und Chat im Netzwerk deines Unternehmens bleiben müssen.

Wann sich Selbsthosting lohnt

  • Eure Sicherheitsrichtlinie erlaubt keine Ticketnamen oder Diskussionen bei Drittanbietern.
  • Du willst es mit internen Tools, Single Sign-on oder deinem eigenen Monitoring verbinden.
  • Du willst die App ändern: Decks, Branding oder neue Funktionen.

Der Stack

TeilTechnologie
Web-AppAngular mit serverseitigem Rendering (Node.js)
API.NET-9-GraphQL-Dienste (Game Engine, User Management) hinter einem HotChocolate-Fusion-Gateway
Echtzeit-UpdatesGraphQL-Subscriptions über WebSockets
SpeicherPostgreSQL für Spiele, Tickets und Stimmen; Redis für Benutzernamen, Chat und den Timer
ObservabilityOpenTelemetry, Prometheus, Loki und Grafana (optional)

Was du brauchst

  • Einen Linux-Server oder eine VM mit Docker. Eine kleine Instanz (2 vCPU, 4 GB RAM) reicht für viele Teams.
  • Einen Reverse Proxy mit TLS, etwa nginx mit Let's Encrypt, für die App und das GraphQL-Gateway.
  • Ein Secret mit mindestens 32 Zeichen zum Signieren der Benutzer-Tokens.

Erste Schritte

  1. Klone das Repository von GitHub.
  2. Starte PostgreSQL und Redis mit Docker Compose.
  3. Starte Game Engine, User Management und das Fusion-Gateway, danach die Web-App.
  4. Richte deinen Reverse Proxy auf die Web-App und das Gateway aus.

Die vollständigen, aktuellen Anleitungen stehen im Setup-Guide und im Deployment-Guide (auf Englisch).

Welche Daten gespeichert werden

  • Benutzernamen: standardmäßig zufällig und nach 24 Stunden gelöscht.
  • Spiele, Tickets und Stimmen: in PostgreSQL gespeichert, damit Teams frühere Schätzungen sehen und einen PDF-Bericht exportieren können.
  • Chat: die letzten 100 Nachrichten pro Spiel, nach 24 Stunden gelöscht.
  • Keine E-Mail-Adressen oder Passwörter: Spieler treten über einen Link bei.

Mitmachen

Issues und Pull Requests sind auf GitHub willkommen. Jedes Release steht im Changelog.
