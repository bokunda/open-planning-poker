Eigene Apps auf der Open-Planning-Poker-API bauen

Jeder Team-Raum hat jetzt eine kleine API zum Lesen und signierte Webhooks. Sie sind kostenlos, dokumentiert und echt und damit ein guter Ort, eigene Tools zu bauen oder Integrationen zu üben.

Was du bauen kannst

  • Ein eigenes Velocity-Dashboard in einer Tabelle, in Grafana oder auf einer statischen Seite, aus /api/v1/sessions.
  • Eine Brücke zu einem Tracker, den wir noch nicht unterstützen: Hör auf ticket.estimated und schreib die Schätzung dorthin, wo dein Team die Arbeit führt.
  • Chat-Benachrichtigungen in Discord, Mattermost oder Matrix, wenn eine Sitzung endet.
  • Ein Lernprojekt: Eine API mit Tokens, Seiten, Limits und signierten Webhooks ist eine realistische Übung für Studierende und Junioren.

In fünf Minuten loslegen

  1. Öffne einen Team-Raum und erstelle als Inhaber unter API und Webhooks ein Token.
  2. Ruf die API auf:
curl -H "Authorization: Bearer opp_…" https://ge.openplanningpoker.com/api/v1/sessions?take=5

Du bekommst die Sitzungen des Teams mit Punkten, Einigkeit beim ersten Abstimmen und Neuabstimmungen, seitenweise mit skip und take. Die Tickets einer Sitzung liefert /api/v1/sessions/{id}/tickets mit vereinbarten Schätzungen und Tracker-Links. Die API liefert nie einzelne Stimmen oder Spielernamen.

Webhooks richtig üben

Füg eine Webhook-Adresse hinzu und du bekommst für jede Schätzung signiertes JSON. Ein kleiner Empfänger in Node zeigt das ganze Muster: den rohen Body lesen, die Signatur prüfen, dann das Ereignis verarbeiten.

import http from 'node:http';
import { verify } from './verify.js'; // the check from the API docs

http.createServer((req, res) => {
  let body = '';
  req.on('data', (chunk) => (body += chunk));
  req.on('end', () => {
    if (!verify(process.env.OPP_WEBHOOK_SECRET, req.headers['x-opp-signature'] ?? '', body)) {
      res.writeHead(401).end();
      return;
    }
    const event = JSON.parse(body);
    if (event.type === 'ticket.estimated') {
      console.log(`${event.data.ticket.externalKey ?? event.data.ticket.name}: ${event.data.ticket.estimate}`);
    }
    res.writeHead(204).end();
  });
}).listen(3000);

Was sich daran zu üben lohnt: Anfragen mit falscher oder alter Signatur ablehnen, Duplikate mit X-OPP-Delivery verwerfen, schnell antworten und langsame Arbeit später erledigen, und in der Liste der Zustellungen die Wiederholungen beobachten, wenn dein Empfänger einen Fehler liefert.

Grenzen und faire Nutzung

60 Anfragen pro Minute und Token, dazu die übliche Grenze pro Adresse. Darüber kommt 429 mit Retry-After. Webhooks gehen nur an öffentliche https-Adressen.
