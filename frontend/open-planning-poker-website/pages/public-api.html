Public API and webhooks

Every team room has a small read-only API and outgoing webhooks. Use them to build your own reports, connect a tool we do not support yet, or practise integrations against a real API.

Authentication

The team owner creates a token in the team room under API and webhooks. It is shown once; we store only its hash. Send it as a bearer token. A token reads only its own team, and the owner can revoke it at any time.

curl -H "Authorization: Bearer opp_…" https://ge.openplanningpoker.com/api/v1/sessions?take=10

Limits

60 requests a minute per token, and the usual limit per address. Above it the API answers 429 with Retry-After: 60. Lists are paged with skip and take (up to 100).

Endpoints

  • GET /api/v1/team: The team's name and description.
  • GET /api/v1/sessions: The planning sessions (sprints), newest first, with points and how each session went.
  • GET /api/v1/sessions/{id}/tickets: The tickets of a session with the agreed estimate and the link to the tracker.

The API never returns single votes or player names: only the numbers the team room already shows.

Errors are JSON: {"error": {"code": "unauthorized", "message": "…"}} with status 401, 404 or 429.

Webhooks

Add an https address and pick the events. ticket.estimated fires when a ticket gets a final estimate (changed is true when an estimate was changed). session.finished fires when the last open ticket of a session gets one.

POST https://your-endpoint.example.com/opp
X-OPP-Event: ticket.estimated
X-OPP-Delivery: 5f0c…            (the same on every retry of this event)
X-OPP-Signature: t=1795291800,v1=9c1d…

{
  "id": "5f0c…", "type": "ticket.estimated", "createdAt": "2026-11-21T20:10:00Z", "teamId": "…",
  "data": {
    "sessionId": "…", "sessionName": "Sprint 12",
    "ticket": { "id": "…", "name": "Login with SSO", "externalKey": "PAY-42", "externalUrl": "…", "estimate": "5" },
    "changed": false
  }
}
{ "type": "session.finished", "data": { "sessionId": "…", "sessionName": "Sprint 12", "ticketCount": 14, "points": 41 } }

Answer with any 2xx within 10 seconds. Failed deliveries are retried after 1, 5 and 30 minutes; the last 20 deliveries are listed in the team room. Use X-OPP-Delivery to drop duplicates. Internal addresses are refused.

Check the signature

X-OPP-Signature is t=<unix time>,v1=<HMAC-SHA256 of "t.body"> with your webhook secret. Reject requests whose time is more than five minutes off.

import crypto from 'node:crypto';

// body: the raw request body as a string, header: the X-OPP-Signature value
export function verify(secret, header, body, toleranceSeconds = 300) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > toleranceSeconds) return false;
  const expected = crypto.createHmac('sha256', secret).update(`${parts.t}.${body}`).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1 ?? ''));
}
import hashlib, hmac, time

def verify(secret: str, header: str, body: str, tolerance: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > tolerance:
        return False
    expected = hmac.new(secret.encode(), f"{parts['t']}.{body}".encode(), hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))

Zapier and n8n

n8n: add a Webhook node (POST), copy its production URL into the team room, then a Code node with the check above, and send the estimate on to Slack, a sheet or your tracker. Zapier: use Webhooks by Zapier → Catch Raw Hook as the trigger so the body stays as sent, then a Code by Zapier step for the check. To read data on a schedule, use an HTTP request node or Webhooks by Zapier → GET with the Authorization header.

Questions

Is the API free?

Yes. The API and webhooks are part of every team room, without a paid plan.

Can I write data through the API?

Not yet: the public API is read-only. Estimates are written by the app itself, which can save them to Jira, GitHub, Linear or Azure DevOps.
