Magic estimation: size a long backlog in minutes

Planning poker takes a few minutes per ticket. With fifty tickets, that is an afternoon. Magic estimation sorts them first, in silence, and saves the talk for the ones the team disagrees on.

How it works

  1. The host opens the sorting board: one column per card of the deck.
  2. Players drag tickets onto the column they think fits, without talking. Anyone may move any ticket.
  3. A ticket moved three times, or moved by someone else to another card, is marked for a talk.
  4. The host sends the marked tickets to a normal vote and turns the rest into final estimates in one step.

When to use it

Use it for refinement of a large backlog, for a new project, or before release planning. Use normal planning poker for the handful of tickets of the next sprint, where the details matter.

The estimates count in velocity, the reports and the reference history like voted ones, and can be saved to Jira, GitHub, Linear or Azure DevOps together.
