Build your own apps on the Open Planning Poker API

Every team room now has a small read-only API and signed webhooks. They are free, documented, and real, which makes them a good place to build your own tools or to practise integration work.

What you can build

  • Your own velocity dashboard in a spreadsheet, Grafana or a static page, from /api/v1/sessions.
  • A bridge to a tracker we do not support yet: listen for ticket.estimated and write the estimate wherever your team keeps work.
  • Chat notifications in Discord, Mattermost or Matrix when a session finishes.
  • A teaching project: an API with tokens, paging, rate limits and signed webhooks is a realistic exercise for students and juniors.

Start in five minutes

  1. Open a team room and, as its owner, create a token under API and webhooks.
  2. Call the API:
curl -H "Authorization: Bearer opp_…" https://ge.openplanningpoker.com/api/v1/sessions?take=5

You get the team's sessions with points, first-vote agreement and re-votes, paged with skip and take. Tickets of a session come from /api/v1/sessions/{id}/tickets with their agreed estimates and tracker links. The API never returns single votes or player names.

Practise webhooks the right way

Add a webhook address and you receive signed JSON for each estimate. A small receiver in Node shows the whole pattern: read the raw body, check the signature, then handle the event.

import http from 'node:http';
import { verify } from './verify.js'; // the check from the API docs

http.createServer((req, res) => {
  let body = '';
  req.on('data', (chunk) => (body += chunk));
  req.on('end', () => {
    if (!verify(process.env.OPP_WEBHOOK_SECRET, req.headers['x-opp-signature'] ?? '', body)) {
      res.writeHead(401).end();
      return;
    }
    const event = JSON.parse(body);
    if (event.type === 'ticket.estimated') {
      console.log(`${event.data.ticket.externalKey ?? event.data.ticket.name}: ${event.data.ticket.estimate}`);
    }
    res.writeHead(204).end();
  });
}).listen(3000);

Things worth practising on it: rejecting requests with a wrong or old signature, dropping duplicates with X-OPP-Delivery, answering fast and doing slow work later, and watching retries in the deliveries list when your receiver returns an error.

Limits and fair use

60 requests a minute per token, plus the usual limit per address. Above it you get 429 with Retry-After. Webhooks go only to public https addresses.

Everything else is in the API documentation: endpoints, events, signature checks in Node and Python, and n8n and Zapier steps.
